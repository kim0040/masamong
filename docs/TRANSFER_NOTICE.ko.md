# 편입 공지 구독

이 문서에서는 편입 공지 기능의 사용자 흐름, 개인정보 경계, 수집 구조, 중복 방지,
장애 처리와 운영 검증 기준을 확인할 수 있습니다. 빠른 사용 방법은
[사용자 가이드](README.ko.md), 전체 문서 구조는 [문서 허브](README.md)에서 확인할 수
있습니다. 자동 수집 여부는 각 공식 사이트의 현재 접근 정책을 따릅니다.

## 사용자에게 보이는 동작

편입 공지는 개인 DM 전용이며 신청한 사람에게만 제공됩니다.

1. 사용자가 마사몽 DM에서 `!편입`을 실행한다.
2. 현재 정책 동의가 없으면 수집 항목과 목적을 보여주는 동의 버튼이 먼저 열린다.
3. 동의한 사용자만 20개 대학 중 1~20곳을 선택할 수 있다.
4. 선택을 저장하면 구독이 활성화된다.
5. 매일 05:35(한국 시간)부터 공개 입학처 목록을 순차 확인하고, 필요한 상세
   페이지 후보만 source별 최대 3건 읽는다.
6. 선택한 대학에 새 글이나 유의미한 목록 제목 수정이 있을 때 설정 시각
   (기본 09:00)에 상세 본문 기반 요약과 공식 링크를 DM한다.
7. 관련 변화가 없으면 아무 메시지도 보내지 않는다.
8. 충남대학교와 국립부경대학교는 공식 `robots.txt`가 전체 자동 접근을 막고 있어
   자동 구독으로 오인시키지 않는다. 같은 화면의 공식 링크 버튼으로 직접 확인한다.

서버 채널에서 명령·메뉴 버튼을 사용하면 DM으로 이동하는 방법만 안내한다. 서버에서는
개인 구독 정보나 공지 결과를 조회·저장·출력하지 않는다. 학교 공지 기능도 같은 원칙으로
DM에서만 동작한다.

주요 명령:

```text
!편입
!편입 최근
!편입 상태
!편입 시간 HH:MM
!편입 구독취소
!편입 재개
!편입 삭제
!개인정보 철회 편입공지
```

`구독취소`는 대학 선택을 보존하고 알림만 중단한다. `삭제`는 대학 선택, 구독과 전달
기록을 삭제하고 편입공지 동의를 철회한다. 동의·철회 감사 이력은 별도 보관된다.

## 대학 선정 범위와 지원 기준

카탈로그의 대학은 최근 모집요강 또는 특정 모집단위에서 TOEIC 등 공인영어가 지원 자격,
전형 점수, 가산점이나 서류 자료로 활용되는 대표 사례가 있는 곳을 중심으로 선정했다.
모든 대학의 모든 학과가 TOEIC으로 선발된다는 뜻은 아니다. 적용 시험, 유효기간, 최저점,
환산 방식과 대상 학과는 매년 바뀔 수 있다.

따라서 알림은 지원 가능 여부를 판정하지 않는다. 사용자는 반드시 해당 알림이 연결한
당해 연도 최종 모집요강을 확인해야 한다.

### 자동 수집 제한 공식 페이지

| 대학 | 제공 방식 | 공식 페이지 |
|---|---|---|
| 충남대학교 | 자동 알림 제외, DM 대시보드 링크 버튼 | 입학처 편입학 공지 |
| 국립부경대학교 | 자동 알림 제외, DM 대시보드 링크 버튼 | 입학처 편입학 공지 |

두 페이지는 공개 열람은 가능하지만 2026-07-29 확인한 공식 `robots.txt`가 전체 자동
접근을 허용하지 않는다. 마사몽은 이를 우회하지 않는다. 검색 색인 기반 대체도 실제
최신 편입 공지 링크를 안정적으로 반환하지 않아 알림 소스로 채택하지 않았다.
`sources.json`의 `manual_sources`는 자동 `sources`와 ID가 겹치면 시작 검증에서
거부된다. 향후 공식 RSS·API가 생기거나 접근 정책이 바뀌면 자동 소스로 승격한다.

2026-07-29 최신 운영 batch에서는 20개 중 15개가 정상 판정됐고 전체 실행은
`partial`이었다. 나머지는 공식 사이트의 `robots.txt` 자동 접근 금지·사이트 응답
변경 등으로 실패 상태가 기록됐다. 이 수치는 운영 환경과 사이트 정책 변경에 따라
달라질 수 있으므로 `latest.json`의 학교별 상태가 현재 사실의 기준이다. 마사몽은
금지 정책을 우회하지 않는다.

## 개인정보 경계

메인 DB에 저장하는 항목:

- Discord 사용자 ID
- 사용자가 선택한 대학 ID 목록
- 구독 활성 상태와 생성·수정 시각
- 알림 시각(기본 09:00 KST)
- 공지별 전달 상태, 유한 재시도 횟수와 성공 시각

수집하지 않는 항목:

- TOEIC·TOEFL·TEPS 점수
- 학력, 전적대학, 지원 학과
- 생년월일, 실명, 전화번호, 이메일

학교 사이트에는 공개 목록 URL과 목록에서 확인한 bounded 상세 URL만 요청한다. Discord
사용자 ID, 대학 선택, 구독 여부나 다른 개인 프로필을 전송하지 않는다. 쿠키와 프록시
상속을 사용하지 않으며, 허용 호스트, 리다이렉트, DNS, 응답 크기와 요청 수를 제한한다.

수집 snapshot SQLite에는 Discord 사용자 데이터가 전혀 없다. 메인 DB의 구독 정보와
공개 snapshot은 인스턴스별 경로로 분리한다.

## 수집과 전달 구조

```text
05:35 systemd one-shot
  -> 공식 목록 최대 20개를 순차 확인
  -> source별 parser와 허용 호스트 검사
  -> 기준선 이후 신규·목록 변경·최신 후보의 상세 본문과 핵심 날짜 발췌
  -> 공개 snapshot SQLite에 upsert
  -> 원자적으로 latest.json 교체
  -> 봇의 1분 전달 tick이 설정 시각이 된 활성·동의 구독자 한 명씩 처리
  -> 성공 또는 유한 retry 상태 기록
```

배치는 상주 루프가 아니다. systemd timer가 하루 한 번 실행하는 one-shot이며:

- 전체 제한 시간 900초
- 목록 URL은 source당 한 개, 상세 후보는 기본 최대 3개
- 서로 다른 host를 포함해 물리 요청 사이 기본 0.35초 간격
- 기본 재시도 최대 1회
- `CPUQuota=25%`, `MemoryMax=256M`, `Nice=10`
- LLM 호출 0회

학교별 결과는 `healthy`, `degraded`, `failed`로 남는다. 일부 실패를 전체 성공으로
숨기지 않는다. 대시보드와 최근 보기에도 `정상/전체` 수를 표시한다.

대학 선택·구독 취소/재개·알림 시각·최근 보기 상호작용은 Discord에 먼저 접수 응답을
보낸 뒤 DB를 처리한다. 버튼과 선택 메뉴 자체는 LLM을 호출하지 않는다. 내부 예외가
생기면 공통 비공개 오류 응답으로 끝내 Discord의 “애플리케이션이 응답하지 않음”만 남는
상태를 방지한다.

## 이전 공지 재전송 방지

- source의 첫 성공 수집은 기준선으로만 저장하고 알림하지 않는다.
- `(user_id, source_id, external_id, revision)`이 전달 중복 키다.
- 새 공식 URL 또는 정규화한 목록 제목이 바뀔 때만 revision이 증가하므로 수정 알림은
  한 번만 가능하다. 목록 제목의 작성일·조회수는 변경 판정 전에 제거한다.
- 상세 본문은 공지 제목 주변 컨테이너를 우선 읽고 조회수 같은 동적 값을 제거해
  요약한다. 상세-only fingerprint 변화는 저장 내용만 갱신하고 revision이나 알림을
  만들지 않는다. 학교 사이트의 공통 메뉴·조회수 변동으로 과거 글이 재전송되는 일을
  막기 위한 안전 경계다.
- 봇 재시작이나 `latest.json` 교체 뒤에도 메인 DB 전달 기록을 사용한다.
- 실패 DM의 payload를 DB에 저장하므로 다음 배치 파일에 덮여도 같은 내용을 유한 재시도한다.
- 실패 뒤 구독 취소·재개, 학교 선택 변경, 동의 철회·재동의가 있었다면 이전 retry를
  되살리지 않는다.
- 잘못된 retry payload는 `failed`로 종결해 1분 무한 루프를 만들지 않는다.

## 기존 구독자의 동의 요청

운세, 학교 공지 또는 편입 공지의 활성 구독이 있지만 현재 정책 동의가 없는 기존 사용자는
기존 설정을 삭제하지 않는다. 자동 발송만 중단하고 정책 버전당 한 번 동의 버튼을 DM한다.

- 활성 구독자만 후보가 된다.
- 구독 취소·중지 사용자는 제외한다.
- 명시적으로 철회한 사용자는 자동 요청 대상에서 제외한다.
- 발송 직전에 활성 상태와 동의 부재를 다시 확인한다.
- 성공 안내는 정책 버전당 한 번, 실패 재시도는 최대 3회다.
- 사용자가 동의하면 보존된 설정으로 기능을 다시 이용할 수 있다.

## 운영 설정

Masamo:

```dotenv
TRANSFER_NOTICE_ENABLED=true
TRANSFER_NOTICE_SOURCE_CONFIG=/srv/masamong/current/transfer_notice/sources.json
TRANSFER_NOTICE_DATABASE=/var/lib/masamong/masamo/transfer_notice/core.db
TRANSFER_NOTICE_OUTPUT_DIR=/var/lib/masamong/masamo/transfer_notice/out
TRANSFER_NOTICE_DELIVERY_MAX_ATTEMPTS=3
TRANSFER_NOTICE_DELIVERY_RETRY_MINUTES=30
TRANSFER_NOTICE_MAX_ITEMS_PER_DM=10
TRANSFER_NOTICE_DELIVERY_HOUR=9
TRANSFER_NOTICE_DELIVERY_MINUTE=0
```

General은 기본 `TRANSFER_NOTICE_ENABLED=false`이며 Masamo의 DB, snapshot, output, timer를
공유하지 않는다.

## 검증

오프라인:

```bash
venv/bin/python -m pytest tests/transfer_notice_spec.py \
  tests/transfer_notice_cog_spec.py -q
venv/bin/python -m py_compile cogs/transfer_notice_cog.py transfer_notice/*.py
```

실제 공식 페이지 기준선 확인:

```bash
venv/bin/python scripts/run_transfer_notice_batch.py \
  --source-config transfer_notice/sources.json \
  --database /tmp/transfer-notice/core.db \
  --output-dir /tmp/transfer-notice/out \
  --lock-file /tmp/transfer-notice/batch.lock \
  --timeout-seconds 600 \
  --max-retries 0 \
  --max-details-per-source 3 \
  --min-request-interval-seconds 0.35
```

새 DB로 실행한 `changes`는 반드시 0이어야 한다. 학교별 상태와 게시물 수를 검토한 뒤에만
운영 기준선으로 사용한다.

# 마사몽 사용 설명서

마사몽은 Discord에서 같이 떠들고, 지난 얘기를 기억하고, 혼자 챙기기 번거로운
것들(날씨, 학교 공지, 편입 공지)을 대신 봐주는 봇이다.

이 문서는 **쓰는 사람**을 위한 설명서다. 내부 구조는
[ARCHITECTURE.ko.md](ARCHITECTURE.ko.md), 설정 키는
[SETTINGS_GUIDE.md](SETTINGS_GUIDE.md), 배포는 [DEPLOYMENT.md](../DEPLOYMENT.md)에 있다.

---

## 처음 써본다면

서버에서는 마사몽을 **멘션**하면 되고, DM에서는 그냥 말을 걸면 된다.

```
@마사몽 오늘 전주 날씨 어때?
@마사몽 우리 저번에 정한 여행 날짜 언제였지?
```

기능을 눈으로 고르고 싶으면 `!메뉴`를 치면 된다. 서버에서는 채널에 작은 실행
버튼만 뜨고, 누르면 **본인에게만** 전체 메뉴가 열린다. Discord는 접두사 명령
메시지 자체를 비공개로 만들 수 없어서 이렇게 한다.

메뉴 홈에는 명령을 전부 늘어놓지 않고 `학교·편입`, `AI·검색·창작`, `날씨·재난`,
`운세`, `커뮤니티`, `개인 설정`, `전체 도움말` 범주만 보여준다. 범주를 고르면 그
범주의 버튼만 바뀌어 나타난다. 날씨·이미지·투표·알림 시각은 입력창에서 바로
실행할 수 있다.

메뉴는 연 사람만 조작할 수 있다. 다른 사람은 각자 `!메뉴`를 치면 된다.
날씨·이미지·랭킹·요약·투표처럼 개인 정보가 아닌 **결과는 채널에 공개**하고,
개인 설정과 관리 화면만 비공개로 유지한다.

전체 명령어는 `!도움`, 개별 사용법은 `!도움 <명령어>`다.

> 개인 설정(운세 등록, 학교 공지, 편입 공지, 개인정보)은 **DM에서만** 열린다.
> 서버에서 눌러도 "DM에서 하세요"라고만 안내하고 개인 정보는 읽지 않는다.

## 대화

**답을 만드는 방식.** 질문을 받으면 먼저 무엇이 필요한지 판단한다. 날씨를 물으면
기상청을 부르고, 최신 소식을 물으면 웹을 찾고, 예전 얘기를 물으면 기억을 뒤진다.
한 번의 대화에서 도구는 최대 3개까지 쓴다.

**질문에 맞는 추론.** 잡담·간단한 회상·조회 결과 정리는 빠른 `low`로 답하고,
여러 조건·충돌·모호한 인물·긴 근거를 함께 풀어야 하면 같은 판단 결과에서 `high`를
고른다. 난이도 판정을 위해 LLM을 한 번 더 부르지 않고, `low` 답을 `high`로 다시
생성하는 자동 재시도도 없다. `high`를 고른 요청은 Discord 진행 메시지도
“조금 더 오래 고민 중”으로 바뀌어 단순 지연과 구분된다.

**기다리는 동안.** 일반 대화와 등록 직후 학교 공지 확인처럼 오래 걸릴 수 있는
작업은 Discord의 기본 입력 중 애니메이션과 단계별 진행 문구를 함께 보여준다.
메뉴·버튼·모달은 Discord의 기본 “생각 중” 표시를 먼저 띄우고, 완료되면 결과나
확인 안내로 닫는다. 애니메이션을 만들려고 메시지를 반복 수정하거나 LLM을 추가
호출하지 않으며, 작업 종료·실패·취소 때 표시용 작업도 함께 끝낸다.

**말투는 서버마다 다르다.** 말투는 봇 설정 파일에 채널 단위로 저장하며, 설정이
없는 채널은 **같은 서버에 설정된 말투를 물려받는다.** 그래서 한 서버 안에서는
말투가 한 가지로 유지되고, A 서버의 말투나 기억이 B 서버 답변에 섞이지 않는다.
설정이 있는 채널은 언제나 자기 설정이 우선한다. 지진 같은 재난 알림만 예외로,
모든 서버에 기상청 발표 그대로의 같은 문구가 간다.

봇이 상황을 알리는 고정 문구(오류·한도·진행 상태)는 서버 말투와 별개로 한 가지
톤을 쓴다. 마사몽 자체가 친구 같은 존재라 딱딱한 격식체는 쓰지 않는다.

**웹 검색.** 출처를 정리해서 답한다. 봇이 단 📰 반응을 누르면 확인된 출처가
펼쳐지고, 반응을 취소하면 다시 접힌다. 검색해온 내용은 참고 자료로 다루지 명령으로
받아들이지 않는다.

**사실 확인.** 일반 상식·의견·창작과 외부 검증이 필요한 질문을 먼저 구분한다.
최신 정보, 수치, 뉴스, 일정, 사용자가 제시한 외부 사실, 지역 교통·시설처럼 내장
지식만으로 확신하기 어려운 내용은 실제 조회가 성공해야만 답한다. 조회가 실패하면
모른다고 밝히며, 검색하지 않고 “찾아볼게”라고 약속하거나 추측을 사실처럼 쓰지 않는다.
시장 브리핑은 웹 기사와 별도로 코스피·코스닥 또는 미국 주요 지수를 직접 확인하고,
원자료에 없는 지수·등락률이 최종 문장에 생기면 전송 전에 제거한다.

**대화 맥락.** 최근 발화는 원문 그대로 두고, 그보다 앞선 구간은 요약해서 쓴다.
더 오래된 것이 필요하면 장기 기억을 찾는다. 전체 로그를 매번 프롬프트에 넣지
않으면서 최근 표현은 그대로 살리기 위해서다.

**기억의 경계.**

- 서버의 공용 대화 기억은 그 서버 안에서만 공유된다
- 내 개인 기억은 다른 사람에게 노출되지 않는다
- DM 기억은 그 DM 안에만 남는다

지금 질문과 상관없는 기억은 일부러 꺼내지 않는다.

**한도.** DM 1:1 대화는 5시간당 30회, 하루 총량도 따로 있다. 한도에 걸리면 언제
풀리는지 알려주고, 서버 채널 대화는 계속 쓸 수 있다.

## 날씨와 재난 알림

```
!날씨              기본 지역
!날씨 전주          지역 지정
!날씨 서울 내일      날짜 지정
```

기상청 실황, 앞으로 6시간 초단기예보, 단기·중기예보, 지금 발효 중인 특보를 함께
보여준다.

**태풍**을 물으면 기상청의 활동 태풍 목록과 최신 분석을 확인해 이름·위치·중심기압·
최대풍속·이동 방향, 공식 한반도 영향 분류와 24시간 전망을 보여준다. 태풍을 명시한
질문에서만 상세 자료를 조회하고 15분간 공유 캐시하므로 일상 날씨 조회 비용은
늘지 않는다. 활동 태풍이 없을 때도 그 사실을 명시해 빈 결과를 추측으로 채우지
않는다.

**지진**은 기상청 발표 후 약 1분 주기로 확인해 자동으로 알린다. 발생 시각과 기상청
발표 시각을 같이 표시한다. 가까운 시간·거리에서 이어지는 지진은 **하나의 메시지를
계속 수정**하면서 총 횟수와 최대 규모를 갱신하고, 멀거나 시간이 떨어진 지진은 새
메시지로 시작한다. 이건 보기 편하라고 묶는 것이지 공식 여진 판정이 아니며, 그 점을
메시지에 밝힌다. 봇을 재시작해도 이미 보낸 지진을 다시 보내지 않는다.

날씨·주식·장소 API가 연달아 실패하면 그 도구만 잠깐 쉬었다가, 60초 뒤 사용자 요청
한 건으로 회복을 확인한다. 실패를 감추고 지어내지 않는다.

## 학교 공지

내 학교·학과·학년에 맞는 공지만 골라 DM으로 보내준다. 현재 14개 대학, 17개
게시판을 지원한다.

### 등록

DM에서 편하게 말하면 된다.

```
전북대 소프트웨어공학과 3학년이고 장학·인턴 공지를 오전 9시에 알려줘
```

학교·과정·학년만 있으면 되고, 캠퍼스·학과·관심사는 원할 때만 말하면 된다.
마사몽이 이해한 내용을 먼저 보여주고 **확인을 받은 뒤에만 저장한다.** 틀렸으면 그
자리에서 말로 고치면 되고, "취소"라고 하면 아무것도 저장하지 않는다.

등록하면 바로 한 번 확인해 결과를 알려주고, 이후에는 매일 새벽 5시에 등록한
학교만 확인한다. 맞는 공지가 없으면 DM도 보내지 않는다.

### 명령어

```
!공지               내 공지 대시보드
!공지 2             결과 2페이지
!공지 등록 <자연어>   등록
!공지 수정 <자연어>   설정 변경
!공지 정보           저장된 설정 보기
!공지 상태           최근 확인 상태
!공지 시간 09:00     알림 시각 변경
!공지 중지 / 재개     알림 끄기 / 켜기
!공지 음소거 <주제>   특정 주제 숨기기
!공지 음소거해제 <주제>
!공지 삭제           데이터 삭제 + 동의 철회
```

### 알아두면 좋은 것

**추천 이유를 항상 보여준다.** "왜 이게 나한테 왔지?"에 답할 수 있게 학부생
대상·관심 분야 일치 같은 근거를 함께 표시한다.

**확실하지 않으면 확실하지 않다고 한다.** 지원 자격을 판단할 수 없으면 "확인
필요"로 표시하고 원문을 보라고 안내한다. 마감 연도를 추론한 경우에도 "연도
추론값이라 원문 확인 필요"라고 밝힌다.

**일부 게시판을 못 읽었으면 알려준다.** "오늘 새 공지 없음"과 "오늘 확인 실패"는
전혀 다른 상황이라 구분해서 보여준다.

**등록금·수강·학적·졸업·병무** 관련 필수 공지는 음소거해도 계속 표시된다.

**학교 사이트에는 여러분 정보를 하나도 보내지 않는다.** Discord ID, 학과, 학년,
관심사 어느 것도 전송하지 않는다. 공개된 게시판을 읽고 봇이 골라내는 방식이다.

이미지로만 된 공지는 링크만 주고, 원문 이미지를 직접 확인해야 한다고 표시한다.

자세한 설계와 계약은 [SCHOOL_NOTICE.ko.md](SCHOOL_NOTICE.ko.md)에 있다.

## 편입 공지

20개 대학 공식 입학처를 매일 새벽 5시 35분에 확인해서, 구독한 대학에 새 공지가
올라오면 DM으로 알려준다. DM 전용이다.

```
!편입               대학 선택 대시보드
!편입 최근           최근 공지
!편입 상태           구독 상태
!편입 구독취소 / 재개  대학 선택은 유지한 채 알림만
!편입 삭제           선택·구독 삭제 + 동의 철회
```

**첫 확인은 알리지 않는다.** 구독 시작 시점의 기존 공지를 전부 쏟아내지 않도록,
처음 수집한 결과는 기준선으로만 쓴다.

**진짜 바뀐 것만 알린다.** 공식 사이트는 조회수나 공용 네비게이션이 수시로
바뀌는데, 그런 변화로는 알림을 보내지 않는다. 새 공지나 제목이 실제로 수정된
경우만이다.

**전형은 매년 바뀐다.** 모든 알림은 최종 확인을 공식 모집요강에서 하라고 안내한다.
"토익/공인영어" 표시는 그 학교에 관련 전형이 있을 수 있다는 뜻이지, 모든 학과가
토익을 본다는 뜻이 아니다.

충남대와 부경대는 공식 `robots.txt`에서 자동 접근을 막고 있다. 자동 구독인 척하지
않고 공식 링크 버튼만 제공한다.

자세한 내용은 [TRANSFER_NOTICE.ko.md](TRANSFER_NOTICE.ko.md)에 있다.

## 운세

```
!운세               오늘의 운세 요약
!운세 상세           자세히
!이번달운세 / !올해운세
!별자리             별자리 운세·순위
!별자리 물병자리      특정 별자리
```

서버에서는 개인 정보 없이 보는 요약 운세만 되고, 개인 운세는 DM에서 등록한 뒤에
쓸 수 있다.

```
!운세 등록           생년월일 등록 (DM)
!운세 구독 07:30     매일 아침 브리핑
!운세 구독 취소
!운세 삭제           데이터 삭제 + 동의 철회
```

구독 시각은 지금보다 최소 5분 뒤로 잡아야 한다. 발송 준비 시간이 필요해서다.

## 이미지

```
!이미지 우주복을 입은 햄스터
```

설명을 그대로 살려서 한 장 그린다. "우리가 갔던 그 카페처럼" 같은 요청을 위해
관련 기억을 참고하되, 대화에 없던 외모나 민감한 특징은 지어내지 않는다.

사용자별·서버별·전체 한도가 있고 요청 전에 미리 확인하므로, 한도를 넘으면 그리기
전에 알려준다. 보통 1분 30초 안에 끝난다.

## 커뮤니티 기능

```
!요약               최근 채널 대화 요약
!랭킹               활동 순위 (명령을 쓴 채널만 집계)
!랭킹 전체
!투표 "회식 장소" "삼겹살" "횟집"
```

`!랭킹`은 **명령을 입력한 그 채널의 기록만** 센다. 서버 전체 합계가 아니다.

`!요약`은 어디까지 요약했는지 서버·채널별로 기억해서, 봇이 재시작해도 그 다음부터
이어서 요약한다. 새 메시지가 없으면 다시 저장하지 않는다. 투표 항목에 공백이
있으면 큰따옴표로 묶으면 된다.

## 개인정보

평소 Discord 대화와 Discord 서버가 주는 정보는 지금까지와 똑같이 동작한다. 봇이
따로 물어보고 저장해서 반복 사용하는 **세 종류의 프로필**만 동의를 받는다.

| 기능 | 받는 정보 |
|---|---|
| 운세 | Discord ID, 생년월일 (선택: 태어난 시각, 성별, 출생지) |
| 학교 공지 | Discord ID, 학교, 과정, 학부 학년 (선택: 캠퍼스, 학과, 관심 주제, 알림 시각, 공지 피드백) |
| 편입 공지 | Discord ID, 선택한 대학, 구독 상태 |

편입 공지는 토익 점수·학력·전공·실명·연락처를 받지 않는다. 말하지 않은 선택
항목은 추측하거나 임의 기본값으로 채우지 않는다.

동의는 DM에서 정책 본문과 버전을 보여준 뒤, **본인이 버튼을 누른 뒤에만** 저장한다.
기능을 쓰다가 동의 화면이 나온 경우, 버튼을 누르면 원래 하던 흐름이 한 번 자동으로
이어진다. 정책 버전이 바뀌면 재동의 전까지 기능이 멈춘다.

```
!개인정보                    현재 동의 상태
!개인정보 동의 운세
!개인정보 동의 학교공지
!개인정보 동의 편입공지
!개인정보 철회 운세
!개인정보 철회 학교공지
!개인정보 철회 편입공지
```

### 철회와 삭제는 다르다

**철회**는 지금부터 그 정보를 쓰지 않는다는 뜻이다. 개인화와 자동 발송이 멈춘다.
쌓인 데이터와 설정은 지우지 않아서, 나중에 다시 동의하면 그대로 이어진다.

**삭제**는 데이터까지 지운다.

```
!운세 삭제
!공지 삭제
!편입 삭제
```

해당 기능의 프로필과 파생 데이터를 지우고 동의도 철회한다. 평소 Discord 대화와
서버 기록은 건드리지 않는다. 동의·철회 기록은 처리 이력으로 남는다.

## 서버 관리자에게

`!관리`는 이 봇의 관리자만 볼 수 있는 비공개 화면이다. 할 수 있는 건 세 가지다.

- 지금 서버의 AI 응답 켜기/끄기
- 지금 채널의 응답 켜기/끄기
- 초대 링크 열기

모델·DB·확인 주기·언어·말투 같은 운영 설정은 **Discord에서 바꿀 수 없다.**
Discord의 서버 소유자·관리자 권한을 갖고 있어도 이 화면은 열리지 않는다. 설정은
서버별로 따로 저장되므로 다른 서버나 다른 마사몽에 영향을 주지 않는다.

`!초대`는 관리자에게만 최소 권한 초대 버튼을 비공개로 보낸다.

## 두 가지 마사몽

코드를 두 벌로 포크하지 않는다. 같은 릴리스를 서로 다른 두 프로세스로 돌린다.

| | 마사모 | 일반 |
|---|---|---|
| 역할 | 운영 중인 기존 커뮤니티 봇 | 새로 만드는 배포 |
| Discord 앱/토큰 | 현재 값 그대로 | 별도 신규 앱/토큰 |
| TiDB | 기존 `masamong` | 신규 `masamong_general` |
| 누적 데이터 | 그대로 보존 | 빈 상태에서 시작 |
| 기억 소스 | Discord + Kakao | Discord만 |
| 학교·편입 공지 | 운영 중 (05:00 / 05:35 timer 소유) | 기본 꺼짐 |

토큰, DB, DB 계정, 저장 경로, 프롬프트, 임베딩 저장소, 관리자 목록, 로그, 서비스를
하나도 공유하지 않는다. 기존 `masamong` DB의 이름을 바꾸거나 새 쪽으로 복사하지도
않는다. 두 프로세스가 같은 DB를 보면 운세 프로필·사용량·기억 키가 섞이므로 분리가
아니다. 잘못 연결되면 **기동 자체가 막힌다.**

자세한 경계와 전환 순서는 [INSTANCE_SEPARATION.ko.md](INSTANCE_SEPARATION.ko.md)에 있다.

## 직접 돌려보기

```bash
git clone https://github.com/kim0040/masamong.git
cd masamong
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env        # 봇 토큰과 LLM 키 입력
python main.py
```

기억/RAG를 쓰려면 CPU용 스택도 설치한다.

```bash
python -m pip install -r requirements-cpu.txt
```

운영에서는 루트 `.env`를 재사용하지 않는다. 프로필 파일을 만들고 프로세스 밖에서
지정한다.

```bash
MASAMONG_ENV_FILE=/etc/masamong/masamo.env PYTHONPATH=. .venv/bin/python main.py
```

기능별 API 키나 feature flag가 없으면 그 기능은 꺼지거나 명확한 오류를 낸다.
명시적 프로필은 필수 Cog 로드에 실패하면 기동을 멈춘다. 절반만 살아 있는 상태를
숨기지 않기 위해서다.

저사양 서버라면 다음 값을 상속에 맡기지 말고 명시한다.

```dotenv
MASAMONG_CPU_THREADS=1
MASAMONG_EXECUTOR_WORKERS=1
AI_MAX_CONCURRENT_PROCESSING=1
LLM_MAX_CONCURRENT_CALLS=1
LLM_CALL_TIMEOUT_SECONDS=120
EMBEDDING_MAX_CONCURRENCY=1
TIDB_STARTER_FREE_PLAN_MODE=true
TOKENIZERS_PARALLELISM=false
BM25_AUTO_REBUILD_ENABLED=false
```

## 테스트

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_bang_commands.py
.venv/bin/python scripts/audit_tracked_secrets.py --secret-env .env
```

운영 DB 점검은 전부 read-only다. TiDB stale-read 트랜잭션에서 실행하므로 쓰기가
물리적으로 거부된다.

```bash
.venv/bin/python scripts/inspect_runtime_readonly.py \
  --expected-profile masamo --expected-db masamong
.venv/bin/python scripts/audit_tidb_free_plan_readonly.py \
  --expected-profile masamo --expected-db masamong
```

`scripts/smoke_*.py`는 실제 API를 호출해 비용이 생길 수 있으므로 오프라인
테스트에서 제외돼 있다. 실행 전 각 스크립트의 `--help`와 최대 호출 수를 확인한다.
의미 대화 smoke처럼 여러 시나리오를 검사하는 스크립트는 한 번보다 많이 호출한다.
